# 天猫换脸防重复提交与原生输入验收

## 改动
- 换脸请求先在批次目录的 SQLite 中记录，再执行生成；同一原图存在提交中或未知回执时拒绝重复请求，关闭页面、改请求编号或重启不会解除。
- 同请求编号成功重放返回原资产，不重复生成；明确供应商拒绝允许用户修复后手动重试。
- 图片/模特/配置在预留提交记录前校验。请求开始后，断连、响应解析、下载/保存等不明失败保守记录为未知。
- API 返回 UNKNOWN_SUBMIT_RESULT / retry_allowed=false；审批批次读回携带原图阻止状态，换脸弹窗显示“提交状态待核实”并禁用提交。
- 客户端未收到后端回执时也先阻止再次点击，引导重新打开审批批次核实；原生成图保持可用。
- 未增加自动解除未知状态或强制重试入口，避免未知受理时重复计费。

## 验证
- 20 项 Python 测试通过，包含并发提交、进程中断残留、断连后换请求编号、已成功请求重放、明确拒绝后重试、响应解析异常，以及 API 重新读取批次的保护状态。
- Vite 构建通过；没有为制造断连再发付费生成，也没有测试云端。
- 源码 Electron：Finder 复制文件后主图、参考图区分别按 ⌘V，成功导入 01-shirt.png / 02-mug.png；“预览”复制 03-mug.png 图片内容后按 ⌘V，成功新增 image.png。
- 当前验收任务“原生输入验收 · 拖入粘贴排序”，2 张主图、1 张参考图，native-paste.jpg 为截图。
- Finder 原生拖入及鼠标拖动排序：自动化已尝试但未观察到落图/顺序改变，尚不能确认是自动化限制还是产品缺陷；已请求人工实操确认，不能标为通过。
