# 抓虾性能实测与代码审查：Windows / 8GB

日期：2026-09-15。审查基线：`d51a4fa41fdad694ec999cb37395df6a7aed47a5` 加当前工作区已有改动。只新增测试探针、证据与报告，未修改产品源码、提交或发布。

## 结论

**还不能认定 i3 / 8GB 下各场景性能验收通过。** 在真实 Windows ARM、4 vCPU、8GB 虚拟机中已复现大图库交互卡顿、同步目录扫描阻塞和缩略图排队延迟。PDF 与图片解码从主线程移出、图库哈希缓存等既有修复仍有效。

本轮发现 4 项性能/资源问题，另 1 项 Windows 测试兼容问题。优先处理大图库全量快照与主线程目录遍历。

## 环境与测量边界

- 宿主：Apple M5 Pro、48GB、macOS；Node 模块实测及 Electron 43.1.0 渲染器 1× / 4× / 6× CPU 降速。
- 客体：UTM「抓虾 Windows 11 ARM 测试」，Windows 11 ARM 26200.9445，4 vCPU，系统可见内存 8,379,136KB（约 8GB），初始可用约 4.4GB。
- Windows 使用 Electron **43.1.0 x64**，经 ARM 转译。4×降速只限制 Chromium 渲染器，不限制 Python、磁盘、主进程；不能换算成某代 i3。
- 当前 Vue 工作台组件生产编译后在独立 Electron 窗口运行，元数据、IPC、缩略图为合成夹具且阻断 HTTP。测试了真实 Vue 状态恢复、选择和持久化；**不是完整应用启动、真实图库图片同时解码、外部平台端到端或完整视觉验收**。未加载完整应用全局样式。
- Windows 通过 Guest Agent 执行，Electron 位于 Session 0；不等同登录用户桌面的 GPU/显示交互验收。截屏已读回核对组件成功渲染。
- 目录、哈希、缩略图与 PDF 探针调用当前真实模块；图片解码/PDF 使用真实 Python。目录夹具为每文件 1KB，不能外推真实大图冷读吞吐量。
- Windows Python 原先缺少 PyMuPDF；仅在 `C:\crawshrimp-perf-20260915\python-deps` 安装 PyMuPDF 1.26.7，通过测试进程 PYTHONPATH 使用。没有验证发行包依赖。
- 下列单次测试是样本值，不是 p95；只有连续选择的 30 次样本计算了 p95。未模拟系统内存耗尽、关闭安全软件或调整虚拟机配置。

## 审查发现

### R1 · P1：单张选择触发整个工作区快照，大图库交互随总量变慢

位置：`app/src/renderer/views/AiVideoWorkflow.vue:2948–2958`、`:9486–9488`。

`styleWorkspaces` 深度监听每次变化都调用 `persistWorkspaceState()`，后者恢复注册表、构建完整快照，再同步 JSON 序列化并写 localStorage。写磁盘 manifest 虽然延迟 450ms，前面的全量快照/localStorage 不受该延迟保护。5,000 张时每个快照约 **2,019,110 个字符**。连续选择 30 次后记录到 34 次 storage 写入，相比初始化后多 30 次。

Windows 5,000 张初始化最大长任务 2,700ms，单张选择 354.6ms；独立连续选择 30 次中位数 113.1ms、p95 139.2ms、最大 166.5ms，无 Vue 错误。只有 20 张卡片渲染也没有消除全量状态成本。这里未采 CPU profile，不把初始化整段长任务全部归因于 JSON.stringify；代码与逐次写入证据明确证明选择时仍走全量保存。

建议：交互只改当前项；增量记录或按款保存，合并持久化任务，把大型序列化移出交互关键路径。验收建议：5,000 张连续选择 p95 <100ms；保存失败仍显式反馈，退出/切换时可恢复。

### R2 · P1：通用目录扫描仍在 Electron 主线程执行同步 I/O

位置：`app/src/main.js:367–417`、`:1468`、`:3265–3267`。

`list-directory-files` IPC 及 AI 视频输入目录调用同步递归 `readdirSync/statSync` 和排序。async IPC 包装不会让其脱离主线程。Windows 5,000 文件 348.3ms，20,000 文件 **1,686.7ms**，调用期间定时心跳均为 0。测试提取当前原函数运行，未替换磁盘操作。AI 视频专用调用限制 500 个匹配文件，但通用入口可到 20,000；上限仅统计匹配结果，不能约束被过滤文件/目录的遍历量。

建议：复用 Worker 或异步有界遍历，增加取消和遍历预算；验证扫描时窗口/停止 IPC 可持续响应。网络盘/杀毒扫描对该路径的实际放大还需实机测试。

### R3 · P2：缩略图只限制并发，未限制/取消等待队列，每张都启动 Python

位置：`app/src/localImageThumbnail.js:35–62`；旧视图请求隔离在 `AiVideoWorkflow.vue:3789–3833`。

并发 2 能保护主线程，但 waiting 数组没有数量、工作区身份、优先级或取消机制。视图切换只阻止旧结果写回，不会撤销已进入主进程的解码请求。每张缩略图均启动独立 Python，重复输入也不会在该层合并。

真实 Windows：20 次缩略图 3,292.7ms，100 次 9,872.8ms；输入为同一 600×1,200 JPG，计量包含每次子进程启动，并非100张不同图的磁盘吞吐。确定性排队注入：100 个旧请求，每个模拟解码 50ms，新请求被排到后面，等待 3,169.9ms（Mac 2,607.8ms）。这是队列机制证明，未声称完整 UI 中一次切换必定积压100项。

建议：按工作区/请求代次取消未启动任务、对可见项优先、合并同图同版本请求，评估持久解码进程。保留坏图拒绝和并发约束。

### R4 · P2：PDF 预览目录成功后持续保留，无生命周期清理

位置：`app/src/pdfPreviewWorker.js:126–132`。仓库 `core` / `app/src` 中没有发现 `pdf-previews` 的其他清理入口。

每次预览 mkdtemp；仅部分超限错误路径删除目录，成功结果和一般失败未清理。探针在同一测试 dataDir 成功预览 5 次，保留 5 个目录；Worker 关闭不会回收。长期重复打开 PDF 会累计磁盘占用；本轮没有把 RSS 的小幅变化认定为内存泄漏。

建议：按会话或最后访问时间/容量清理，保留正在使用的页；失败/取消时清理部分输出。验证清理不会使正在框选的页面失效。

### R5 · P3：Windows 路径大小写归一化未反映在测试预期

位置：`app/src/balaWorkspaceFiles.test.js:183`；实现 `balaWorkspaceFiles.js:18–20`。

Windows 定向 47 项测试：46 通过、1 失败。测试期待保留原大小写的 realpath，但实现把 Windows rootIdentity 转小写后持久化。该用例已成功删除目标图片，仅最后 roots 比较失败。应修改跨平台断言，不据此认定产品删除失败。本轮保留原测试及失败证据。
