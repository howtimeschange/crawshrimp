# 巴拉鞋品专属模型识别

策略值 `bala_specialist`。通过现有鞋品任务配置选择，下载与最终图包导出仍走原脚本；本地子进程负责 DINOv2-S/14 分类、灰底配对、雪地鞋口定位和 OCR。模型缺失、身份冲突或品类未填写时明确失败，不调用大模型兜底。既有找图模式保留，默认选择「【推荐】巴拉鞋品专属模型识别」。

## 应用内置依赖

用户只选择「巴拉鞋品专属模型识别」，不配置模型目录或 Python。模型位于 `core/shoe_specialist/assets`，随 `python-scripts/core` 打包；推理子进程使用应用自身的 `sys.executable`。旧任务里的路径参数不再进入执行器。

macOS（arm64/x64）和 Windows（x64）使用同一套 CPU ONNX DINOv2 与 RapidOCR 中文模型，OCR 权重包含在固定版本的 Python wheel 中，无需下载、系统 OCR、Swift 或 PyTorch。专属模式的 TMQ 红框直接采用已核验的款号坐标，不再调用系统 Tesseract 二次改框。EAN13 使用 zxing-cpp 从图片解码，避免 OCR 漏掉条码首位后误识别为款号。表格颜色字段按文字框空间关系匹配。

开发/打包时运行 `bash app/scripts/download-python.sh` 安装 `core/requirements.txt`，然后正常打包。`after-pack.js` 检查推理依赖、OCR 权重、DINO 模型与分类头 SHA256，缺失或损坏即阻止构建。构建期替换模型使用 `scripts/install_bala_shoe_bundle.py --source <verified-bundle>`；这不是用户安装步骤。

推理完全离线；资源损坏明确报错，不切换大模型。开发回归报告位于 `artifacts/shoe-specialist-portable-20260916`，测试平台与范围以报告为准。

## 输入与输出

- 款号品类表必须明确填写运动、休闲、婴童或雪地；204426146037 本轮按用户确认为婴童。没有将13款号/正确图片ID写入预测器。
- 推理输入只含图片来源、款号、色码、品类、文件哈希，拒绝标签字段。鞋盒 OCR 必须匹配完整12位款号及5位色码，并提供唯一款号文字框。
- TMZ1–4 优先使用前景像素、轮廓均一致的灰底源图；雪地 TMZ4/WPZ4 使用模板鞋口定位裁图。TMZ5 使用标准命名源图，WPZ15 选择同色灰底配对。
- 复用原脚本主推色、O、TMS、WPZ、YQ、YK、YX、渠道 PNG、TMQ、原图保留及最终导出规则；同名不同尺码照片绑定实际选中的路径，避免下载顺序覆盖。
- YX 阈值拒选只表示小模型未选中，报告保留待核验，不自动断言素材不存在。
- `专属模型选图证据` 记录实际源图哈希；不伪造多模型共识或大模型语义审核。

这套权重使用13款训练；本批回归不等于独立新款100%正确率。分类分数未校准，不是生产合格概率。当前整批错误会保留下载素材与分析目录并报错，不保证逐款容错续跑。
