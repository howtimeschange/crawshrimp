# 鞋品找图与完整导出改动摘要

本次汇总从已有标签优先/双模板链路之后累积的鞋品实现、测试、模型资源及打包改动。默认流程为 **【推荐】巴拉鞋品专属模型识别**，其他找图模式继续保留。

## 专属模型与身份核验

- 新增 `bala_specialist` 策略，使用 DINOv2-S/14 空间特征与按品类、槽位训练的分类头，包含 YX 功能卡挑选；从推理输入排除训练标签字段。
- 四类模板分别处理运动、休闲、婴童、雪地。款号、色码、云盘来源与鞋盒 OCR 必须匹配；品类表须明确填写品类。204426146037 按用户确认归婴童。
- 对同名但不同尺码目录的图片绑定实际路径与哈希，避免下载顺序覆盖；不把错误品类或错误款色作为训练、导出依据。
- 运动 TMZ4 按模板选择翘跟露底；婴童、休闲使用落地后侧；雪地使用 DINO 稠密对应定位鞋口，按模板的空间关系和占比裁切原图，不合成或拉伸鞋子。
- 白底/灰底配对同时核对前景像素与轮廓。模型、输入与选图来源有哈希记录，推理失败不回退大模型。

## 完整图包与缺图处理

复用原脚本的 TMZ、WPZ、TMS、O、YQ、YK、YX、JDT、TMT、WPT、TMQ、主推色和原始素材保留规则，不再只交付少量分类槽位。O 图由对应品类规则派生，雪地 TMZ4/WPZ4 使用相同鞋口裁图。

- YX 拒选保留待核验原因，不以阈值拒选直接断言完整素材不存在。
- TMQ 红框直接使用专属 OCR 已核验的款号坐标，跳过系统 OCR 二次改框；其他旧模式保留原有处理。
- WPT 透明 PNG 增加受质量约束的量化、透明处理和有限缩放。无法满足体积与画质时保留可用源文件并记录问题。
- 有效图保留，已通过且来源未变化的槽位锁定；失败、未知和缺图分别记录，问题成品隔离，避免被当成合格交付。

## 可选模板审核与修复链路

新增蒙版直接初选、候选观察目录、按款模板/原图/成品看板审核、已选原图独立事实核验、终审与质量统计模块。蒙版分数只用于提出候选，不作为通过证明。

看板逐行核对鞋数、拍摄类型、视面、鞋轴、落地关系、鞋侧、背景和功能卡；标签从姿势池排除。修复只处理问题槽位，YQ3 随 TMZ3 的同侧参照失效/更新；未知或互相矛盾的结论保留原图，有界复核，不循环换模型求通过。

模板、输入、原图、成品、模型路由和规则共同形成缓存指纹。保留测量式姿势比较实验模块，用于局部几何事实回归，不将实验结果宣称为生产准确率。

## 并发、容错与计量

- 款级和请求并发默认各 8，所有阶段共享请求信号量；图片预处理另有限流，缓存灰底配对特征并在源图变化时失效。
- 批次首轮、复核、补选、重导出分阶段执行；成功款色复用，失败款色有界重试，已完成槽位不被整批覆盖。
- 大模型可选链路默认执行顺序为官方 DeepSeek → Astra，姿势看板模型独立配置。无效 JSON、单次静默超时不会冻结整批；连续静默触发冷却，成功响应恢复可恢复故障，鉴权/限流状态保留。
- 请求记录款号、颜色、业务阶段、用途、重试与实际路由。流式接口保留结束后的 usage 数字字段，不记录推理正文；空白片段不延长有效活动期限。

## 应用内置与跨平台 OCR

模型目录和 Python 路径不再由用户配置，旧任务里的这两个参数不进入执行器。DINOv2 转换为两种输入尺寸的 ONNX，分类头、YX 模型与雪地模板随应用资源打包，使用应用自身 Python 启动离线子进程。

macOS/Windows 共用 ONNX Runtime、RapidOCR 中文权重及 zxing-cpp 条码解码。对漏读首位的 EAN13，仅依据实际条码解码结果纠正；表格标签按文字框位置关联颜色栏。运行时无需 PyTorch、Swift、系统 OCR 或在线下载。

构建阶段检查 Python 依赖、OCR 权重、模型资源及 SHA256。构建期资源安装器只接受已核验 ONNX bundle；界面使用推荐名称并默认选中，仍可切换旧模式。
