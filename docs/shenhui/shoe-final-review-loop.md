# 鞋品蒙版直接初选与按款看板审核

当前默认已切换为 `bala_specialist`（【推荐】巴拉鞋品专属模型识别），使用内置离线模型；见 [完整改动摘要](shoe-changes-2026-09-16.md)。本文保留可选的大模型看板审核链路及其历史实验记录。

## 可选看板审核链路（mask_board_review）

标签识别与框选 → 本地蒙版初选 → 按款号拼模板/原图/成品看板 → 模型逐行审核及已选原图独立事实核验 → 仅问题图位AI补选或加工修正 → 增量复审。

- 初选不调用模型观察整池或逐位精选。蒙版按几何相似度提出候选，整体分配避免不兼容图位复用相同前景。已核验标签从姿势池排除，保留用于wpz6/tmq；标准身份单独约束。所有初选均未获批准。
- 看板按款号组织，可跨同款颜色分页；每页最多4行，1864像素宽，三列固定为单格模板、所选原图和真实成品。行标题用深色底，每格有封闭粗边框，行间留白24像素、列间16像素；每格重复完整行号及列角色，模板/原图/成品标题分别用浅黄/浅蓝/浅绿，减少跨格误读。模型实际收到看板JPEG，前序通过结果、蒙版分数和选图理由不进入审核提示。yq3额外显示本色tmz3参照，参照未通过时不得放行依赖它的同侧结论。
- 模型先观察中列原图，描述实际鞋只数、主要视面和互斥的拍摄类型，再看模板并逐项返回规则true/false/null，最后检查导出。这样减少把模板内容套到原图上的误判；仍是同一个请求。代码另检查数量、拍摄类型、姿态事实、尺寸、透明通道、文件映射。鞋盒的0只鞋是有效拒绝；看不清、缺行和坏JSON是审核未知。同页已返回有效结论的行保留，只有未知行生成2764像素宽的单行放大看板，按该图位配置的审核路由复核；每张新图在同次审核内最多两次机会，不等待整批下一轮补选。
- 总判断通过但检查项为false时保留为未知，不将原图加入排除清单。内侧/外侧判断依赖的tmz3未通过或缺失时，yq3的通过和拒绝结论都须重新核对。同源不同成品行意见冲突也保留原图。
- 雪地tmz4按模板强调鞋口/绒毛内里近景；整鞋俯斜只露少量内里不能替代。镜像、配色、鞋帮高低、附着的IP装饰不构成姿态拒绝理由。
- 不合格源图才进入排除清单。AI补选只处理问题图位，访问完整剩余素材；其他图位锁定。独立问题图位并发，yq3等待新的tmz3参照。tmz3换源时清除旧参照产生的yq3拒绝名单，新配对仍须审核，且必须有可辨鞋侧和具体侧板配对证据。补选是提议，必须重新导出并回到同一看板审核器；没有合适素材可以缺图。
- 原图、模板、成品、依赖参照、规则和模型顺序共同构成每行缓存指纹。相同且已通过的行不再请求；同一未知指纹最多初次及一次后续复审。加工错误不排除原图，源图不变不无故重导出。
- 姿势与功能卡看板单独指定审核模型，当前默认Astra low；无法确认时仅对未知行放大复审，次数用尽后保留未知。标签、补选以及标准图/辅助加工看板保持官方DeepSeek → 森马Astra。官方通用看板使用low推理强度，已选原图独立核验使用high，标签和补选保持官方默认。配置可选择官方姿势看板或跟随执行顺序作对照。真实HTTP payload记录reasoning_effort，不能只以UI文案证明生效。Terra和森马DeepSeek需要手动扩展才会进入链路。所有标签/审核/补选共用8请求上限，款数默认8；不同审核模型分别分页，图片构建另受内存信号量限制。

`style-review-boards/`保存实际请求看板、逐页提示/结果/哈希；`latest-index.json`索引当前各行；各款色`export-review/results.json`记录源图错误、加工错误和未知。`global-assignment.json`记录本地初选来源及0次初选模型请求。`board-repair-*/`记录问题图位检索证据。

配置仍提供`sequential_templates`作为“蒙版+模型精选+按款看板审核”对照，以下描述其中的候选观察与分配过程。

## 处理流程

1. 标签与品类先核验。本地蒙版/OCR计算各图位前三候选，合并去重后每4张交模型观察原图：鞋只数、摆放、视面、鞋轴、后跟、鞋底、鞋侧、功能卡和背景。标准身份源图始终保留；蒙版不可用则退回完整候选池。分数只调整候选顺序，不直接批准图片。即使独立观察错分姿势，前三候选仍作为提议保留，由模板与原图的精确审核裁决。
2. 观察缓存按图片字节、提示版本、模型及路由地址区分；输入变化重新观察。失败结果记为未知，不写成无图。每张候选保留事实及来源。
3. 程序按品类图位规则整体分配，优先满足覆盖率，再比较证据得分。图片家族不能占用不兼容图位；tmz2/yq1共享，标准图与灰底配对，yq3与tmz3鞋侧结构约束。没有候选时记录检索不足或分配冲突，不宣称素材不存在。
4. 首轮各款完成后，统一审核器按款及独立图位并发审核。模型同时看模板、所选原图与实际成品。同语义图位的派生文件合并进一次审核，逐文件返回处理完整性结果；尺寸、透明度和源图映射由代码检查。
5. 审核分为 accepted、source_invalid、source_missing、export_invalid、review_unknown。已检查完整素材并确定没有功能卡时另记 optional_absent，固定图位统计仍保留缺失项。源图错误才进入替代候选排除表；加工错误仅重导出；接口异常保留候选并恢复审核。独立观察和审核有明确事实冲突时，按配置的下一实际模型裁决；普通视觉否决不会自动轮换求通过。
6. 补齐时再观察此前暂缓的原图，已完成观察仍按输入哈希复用。重分配失败时查看完整剩余池作补充检索；修复只提出候选，交回统一审核器。最多两轮，无进展停止，输出合格图片与未解决清单。

蒙版计划保存在 `mask-shortlist/plan.json`，包含每张原图和模板哈希、OCR框、各图位全部排名、首次候选、耗时。`candidate-catalog/index.json` 区分已观察、接口未知、尚未观察。功能卡不存在必须通过完整原图池检查，不能由前三候选推断。

精确审核使用单格模板，避免把重复示例误数成多只鞋。模板鞋数与图位定义矛盾属于审核事实错误，不能据此通过或排除原图。争议复核只接收待核对的事实名称，不带入前序取值；鞋侧判断先比较结构位置，不能仅把印花差异臆称为内侧标记。

两次独立精确审核对原图是否符合图位给出相反结论时，记为 review_unknown，保留候选进入有上限的复核流程。后一模型的意见不能直接覆盖前一模型而造成误选或误删。

WPT透明PNG优先保持尺寸并限制可见区域色彩误差。2026-09-16 的业务配置允许有限缩放满足600KB，仍不允许放宽可见色彩误差；不能达标时保留可用文件并提示人工处理，不将超限冒充通过。

模型请求共用一个信号量，默认8、可配置1–32。款并发默认8、可配置1–8。看板按页并发，所有请求共享同一限制。成品预处理另限制2个同时操作，避免嵌套请求与图片操作无限叠加。

## 审核证据与状态

`review-context.json` 保存品类模板、候选路径、前序观察与选择、导出清单；不保存密钥。前序通过不代表最终正确。只有相同原图、全部导出字节、模板、鞋侧参照、品类、背景规则、模型与审核提示可以复用终审。

`_unresolved_exports` 保存明确不合格的文件；`_unreviewed_exports` 保存审核未知文件。两者都不能冒充合格输出；原候选和诊断记录保持可追溯。`unresolved-selections.json` 分别记录待补图、成品问题与审核未知。

## 质量与费用

固定人工正反例记录输入哈希、模板哈希、真值来源和版本。分别报告错图放行、正确图误拒、审核未知、应交图位覆盖率和已交图正确率。缺图保留在覆盖率分母；人工待审不得计入正确图。

先跑固定回归、单款实际图包验证，再交独立任务进行13款测试。基线与最终任务已创建，后续改进继续使用既有最终任务，不重复新建。其余款只称为本轮改动未用于调参的款，历史已测试过，不能宣称完全未见样本。

2026-09-15的看板v2两款实测有70张现存成品，64张视觉正确，6张错误被放行；不能将程序accepted当作人工真值。v4把这6张归并为4个源图负例加入固定回归，15例全部正确、0误放/误拒/未知，6个官方请求、71.707秒、官方¥0.18926708。该控制结果只证明这组已知样本，完整链路和13款验收须独立报告。

v4雪地单款完整链路仍有2张悬空双鞋误放。对完全相同的实际看板，官方33.853秒漏掉该错误，Astra盲审39.378秒正确拒绝。因此v5将姿势看板与标签/补选模型分开，避免增加一次全量重复审核。v4还发现后处理误读尚未写回的初始状态，导致正确yq3被隔离；v5只把真正的技术失败计入坏参照，并统一结果表与看板索引状态。

v5模型返回的额外无关检查项不影响本行，要求中的字段仍必须全部覆盖。单鞋竖侧图允许倾斜支撑；禁止双鞋悬空的规则不能套到单鞋。坐标与方向拒绝自相矛盾时保留原图放大复核。

耗时区分初选处理、统一审核、修复和包含整批等待的款级完成时间。每次真实请求记录阶段、款色、实际模型和usage；输出token已含推理，不能重复计费。按用户要求，人民币费用只统计DeepSeek官方，森马网关调用不计费；官方失败请求缺失usage单独标记未知，不能当作零费用。所有诊断费用另列。

两轮13款测试显式使用 `--workers 8 --request-workers 8`。先通过13款调度峰值8的自测；每轮根据实际style_start/style_end及request事件，记录并核实款处理峰值8、模型请求峰值不超过8，不只读取配置值。

## v6 真实漏判后的独立原图核验

v5 雪地单款独立验收为29/34视觉正确、5张误收：悬空双鞋缺完整外底，以及两色俯视图替代纵向侧面。拆成多张行附件与单换审核模型仍漏判。v6在看板通过或总票与检查项冲突时，只发送单张已选原图作中性事实观察：不带模板、目标图位、成品、其他图片或前序结论。独立请求沿用执行模型顺序，官方使用high；看板仍用其单独配置。未知不等于源图错误，独立的正面意见不能把看板未知升级为通过。明确基本事实矛盾进入问题图位补选。

原图观察以内容、提示和实际路由身份去重；同源别名并发共用一个请求。模型请求仍受整批8请求上限约束；失败或不明观察不永久缓存。证据在style-review-boards/source-facts，最终行结果附带观察路径。鞋轴方向与同侧精确比较仍由看板审核；中性事实观察无法保证所有细微斜前/正侧区分，必须保留独立13款验收。

基准脚本不再使用周期faulthandler栈转储：v5业务complete后诊断线程自旋、退出卡在cancel，外部采样保存后自有进程以SIGTERM结束（exit143）。416.243秒与CPU记录受到诊断线程干扰，不能作为干净性能对照，也不能记作进程正常完成。
