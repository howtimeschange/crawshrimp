## 1. 目标与边界

新增独立适配包「森马上新助手」（建议 ID `semir-launch-assistant`），参考现有 `shenhui-new-arrival` 的任务拆分、宿主下载与结果表机制，围绕森马男女装上新批次完成前置资料准备：明确本批款色和上新尺码，收集素材、制单、SKU、洗唛和质检报告，生成可复核的资料包及差异清单，交给 Listingify 建档规则和运营审核。

本包的目标是**准备和核对资料**。不在本次规划中设计为自动创建深绘档案、上传云盘、上传深绘或发布商品。既有深绘上传任务单独存在，是否未来连接、由谁触发，另行确认。计划中所称查询/下载均需已有授权和登录；导出本地文件属于读取源系统后的本地落盘，不等于写入业务系统。

## 4. 身份、范围与冲突规则

1. 一次任务固定 `batch_id`、品牌、季节、批次、渠道/目标、主表来源、导出时间和文件哈希。品牌、租户/商户、经营目标的正式身份由 Listingify 协商确定；未确认时不凭款号猜租户。每次重跑创建新快照或明确关联前一批，不覆盖历史证据。
2. 业务范围以经确认的男女装主表快照为输入；主表的计划颜色和上新尺码与 SKU 全量、制单尺码表是三套独立集合。差集可报告，不静默扩充、删改或伪造 SKU。款号、款色、企业码、尺码编码均按字符串处理；允许完整字母数字款号，色号保留前导零。
3. 期望 SKU 不是默认所有颜色和尺码的笛卡尔积事实：先以主表范围生成**候选核对集合**，再核对实际 MDM 导出是否存在及业务是否要求该组合；缺失与不适用需人工裁定。企业码空、重复、售价冲突均列出来源行。
4. 制单测量值按款、阶段、修订、量点、度法、单位、尺码记录。半围/全围、CN/EUR/US 标签、空白/零不自动互换；PLM 回退和多份制单冲突必须暴露。上新尺码只限制交付范围，不能改变原始制单。
5. 云盘静物/模特、SCM 洗唛/吊牌、检测报告各保留来源及适用范围；同款不同色成分、标签和报告不得扩大到整款。报告是否必需、适用色、有效期、羽绒类型和充绒量以可验证资料及业务确认决定。
6. 冲突及业务确认应生成可追溯记录：问题 ID、来源快照、原始值、选择值、原因、操作人和时间；新来源版本变化后复核决策是否仍有效。资料未齐与无要求是不同状态。

## 5. 本地交付契约草案

以下是与 Listingify 讨论的**提议**，尚非已实现 API 或最终格式。设计先用本地文件交接，等双方确认数据契约和权限后再决定接口。

```text
森马上新_季节_批次_快照ID/
  manifest.json                 # schema_version、批次身份、来源版本、覆盖与哈希
  范围/主表快照.xlsx            # 原文件只读复制；附解析结果和来源行
  数据/SKU原始明细.xlsx
  数据/PLM尺码_宽表长表.xlsx
  数据/SCM成分及附件清单.xlsx
  原件/款号/款色/{静物,模特,洗唛,吊牌,质检,制单}/...
  成品/款号/...                 # 审核后的图包；是否 ZIP 按目标要求
  结果/资料对账.xlsx            # 汇总、款色、SKU、测量点、附件、异常、决定
  结果/交接清单.jsonl           # 机器可读逐条记录
```

单条记录至少包含 `schema_version`、`batch_id`、品牌、目标标识、`style_code`、`color_code`、`size_code/size_name`（适用时）、资源角色、来源系统与原始记录 ID/路径、源文件哈希、采集时间、源版本/阶段、相对文件路径、处理动作、结果状态、错误码及审核状态。相对路径必须位于包根内；不记录令牌、Cookie 或签名下载链接。颜色、尺码和报告字段按适用粒度填写，不能把缺失属性当作全款通用。

来源级状态建议为 `complete / partial / error / not_required / not_checked`；个体级区分 `found / missing / out_of_scope / conflict / pending_review / verified`。`complete` 只表示该来源在确认查询范围内已完整读完并核对结束信号，不等于商品可发布。保留请求/记录 ID 和中断点，重试只处理确定失败/未执行项目；对未知结果先查询回读，不盲目重复操作。局部结果要保留并标明覆盖比例和失败原因。

## 7. Listingify 协作与待决事项
