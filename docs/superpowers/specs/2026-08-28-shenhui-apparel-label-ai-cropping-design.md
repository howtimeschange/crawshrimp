# 【服饰】整理深绘上新图包：吊牌/洗唛识别与裁图设计

## 背景

`【服饰】整理深绘上新图包`（task id：`prepare_upload_package`）目前先在森马云盘中按款号收集模特图和静物图，再由浏览器侧脚本按文件名、父目录和扩展名决定保留或过滤，最后由后端整理并压缩图包。

现有吊牌/洗唛链路存在四个问题：

1. 主服饰图包原实现没有把 `yq1` 和 `yq2` 分别识别为吊牌和洗唛。
2. PDF 类型主要依赖文件名或父目录中的“吊牌/合格证/洗唛/水洗”等关键词；文件名不明确时容易误判或漏判。
3. PDF 截图使用固定比例框，并对每一页机械裁切，不能在一页多张、多页、多款色、多尺码版式中选择正确标签。
4. 文件名或路径无法识别图片内容中的手写占位吊牌、“无吊牌”“无水洗”等废图。

真实样例说明固定框不足：`202426107206` 的四页合格证 PDF 包含两个色号及 90–175 多个尺码，旧框裁出了背面 Logo，而不是需要的 110 尺码正面吊牌。`201426105102` 的历史产物中也出现过 `yq1/yq2` 内容角色或款号不一致。

## 目标

只为 `prepare_upload_package` 增加一个可审计的吊牌/洗唛闭环：

- 现成 `yq1/yq2` 按角色优先，避免重复处理 PDF。
- 只对缺失的吊牌或洗唛角色使用 PDF 文本、OCR、视觉模型和动态裁图。
- 多尺码时优先选择 110；没有 110 时选择最接近且大于 110 的尺码；完全没有 110 及以上尺码时选择最大的小尺码。
- 剔除手写纸覆盖真实标签的占位图，以及内容或路径明确表示“无吊牌/无水洗/废图”的素材。
- 输出和结果表能解释每张图为什么入选、跳过或失败。

## 严格作用域

本设计只改变以下任务的行为：

- 适配器：`shenhui-new-arrival`
- 任务：`prepare_upload_package`
- UI 名称：`【服饰】整理深绘上新图包`

以下任务和流程必须保持原行为：

- `batch_label_tile_download`（批量下载吊牌/洗唛/平铺图）
- `pdf_batch_screenshot`（PDF 批量截图）
- 鞋品图包及鞋品姿势识别
- 其他适配器和服饰下载任务

后端即使增加共享函数，也只能从 `task_id == "prepare_upload_package"` 的最终整理分支调用。不得把新逻辑挂到通用 PDF 批量截图或批量吊牌下载分支。

## 已确认的业务规则

### `yq1/yq2` 角色级短路

- `yq1` 表示吊牌。
- `yq2` 表示洗唛。
- 款号目录已有不带款色前缀的有效 `yq1` 时，直接保留它，并对整个款号跳过吊牌 PDF。
- 款号目录已有不带款色前缀的有效 `yq2` 时，直接保留它，并对整个款号跳过洗唛 PDF。
- 两者都存在时，不为该款号调用吊牌/洗唛 PDF 识别和裁图。
- 如果现成 yq 文件带有明确款色前缀，则只锁定该款色的对应角色，其他款色仍可补图。
- 只缺一个角色时，仅补缺失角色。
- 支持 `yq1.jpg`、`yq(1).jpg`、`yq 1.png`、`yq一.*` 及对应 `yq2` 变体；匹配必须以完整标记为边界，避免把无关数字当成角色。

“有效”至少要求：

- 文件类型是受支持的图片格式。
- 文件名和显式父目录未命中废图规则。
- 图片能正常打开且像素尺寸有效。
- 最终废图门禁未判定为手写占位图或“无吊牌/无水洗”图片。

`yq1/yq2` 的短路含义是跳过角色判定、PDF 选择、多尺码选择和裁图，不是绕过废图门禁。

### 废图规则

以下素材不得进入图包：

- 文件名或显式父目录包含“无吊牌、无吊卡、无挂牌、无合格证、无水洗、无洗唛、无洗标、无洗水、废图、作废、无效”等标记。
- 图片主体是白纸或便签覆盖真实吊牌，纸上主要为手写款号、色号、尺码或备注。
- 图片内容直接写有“无吊牌”“无水洗”等否定信息。
- 识别出的印刷款号与当前款号不一致。
- 无法证明为真实印刷吊牌或洗唛、且模型和本地证据不足的可疑候选。

允许真实印刷吊牌上的少量人工勾画或质检笔迹；只有手写纸承担主要标签内容、真实标签被遮挡或缺失时才判为手写占位图。

### 多尺码排序

对同一款号、色号、角色的有效候选，尺码优先级为：

1. 精确尺码 110。
2. 没有 110 时，选择最接近 110 且大于 110 的尺码，例如 120 优先于 130。
3. 完全没有 110 及以上尺码时，选择最大的小尺码，例如 100 优先于 90。
4. 同尺码候选按款号一致、色号一致、标签完整度、清晰度和识别置信度排序。

包含完整尺码表的单张洗唛不因出现多个尺码数字而拆成多个候选；只有一页或一张图中存在多个独立标签单元时才进行单元级尺码选择。

## 方案选择

采用混合方案：确定性规则和本地证据优先，视觉模型只负责内容语义、复杂版式和坐标，最终由本地代码裁切和验收。

不采用纯规则/OCR，因为它无法稳定识别手写覆盖和任意 PDF 版式。不采用纯模型，因为款号、尺码和坐标必须有本地硬校验，不能直接相信模型输出。

## 架构

### 浏览器侧候选收集

`prepare-upload-package.js` 负责：

1. 继续收集模特图、静物图和 PDF。
2. 识别 `yq1/yq2` 变体并写入明确角色元数据。
3. 在下载前按文件名和显式父目录过滤废图。
4. PDF 只作为候选下载，不在浏览器侧用“纯款号 PDF”猜测洗唛。
5. 为结果行保留原文件名、原云盘路径、角色提示和款色编码，供后端核验。

浏览器侧不调用视觉模型，也不生成最终裁框。

### 后端角色级编排

`prepare_upload_package` 的最终整理分支先按款号、再按款色分组：

1. 打开并校验现成 `yq1/yq2`。
2. 对通过废图门禁的现成 yq 建立角色锁。
3. 根据角色锁计算缺失角色。
4. 仅向缺失角色提供相关图片和 PDF 候选。
5. 将入选裁图写回款号目录，并更新结果行。

不带款色前缀的现成 yq 建立款号级角色锁；带明确款色前缀的现成 yq 建立款色级角色锁。这样既满足“图包已有 `yq1/yq2` 就不重复处理”，也避免某个色号的专用 yq 误锁其他色号。

### PDF 和图片预处理

- PDF 使用 PyMuPDF 逐页渲染，并同时提取页文本和带坐标的文字信息。
- 普通图片先执行 EXIF 方向校正，再生成有尺寸上限的识别预览。
- 对 PDF 页优先使用矢量文字定位款号、色号和尺码；普通图片使用本地 OCR 提供文字硬事实。
- 原始文件保留到本轮判定完成，防止裁切或模型失败后丢失审计证据。

### 智能识别调度

只分析吊牌/洗唛候选，不扫描全部服饰商品图。

第一阶段并发执行：

- PDF 文本或本地 OCR。
- 两个视觉模型对同一批候选做结构化识别。

视觉模型返回数组，每个候选单元包含：

- `kind`：`hang_tag`、`wash_label`、`non_label`。
- `printed_label`：是否为真实印刷标签。
- `handwritten_placeholder`：是否为手写纸占位。
- `waste_reason`：废图原因。
- `style_code`、`color_code`、`sizes`。
- 归一化裁框 `bbox`。
- `confidence` 和可核验的简短证据。

两个初审模型与 OCR/PDF 文本一致时直接进入本地验证；模型分歧、置信度不足、款号或尺码冲突时，只对冲突单元调用更强模型复核。模型调用按款号批量并发，不对每个候选串行等待。

默认使用已配置的 `gpt-5.6-terra` 和 `gpt-5.6-luna` 并发初审，使用 `gpt-5.6-sol` 处理分歧。若其中某个路由未配置，则从现有 `llm_gateway` 中选择已配置且支持视觉输入的模型补位；不得使用不支持视觉输入的纯文本模型。

模型不可用时：

- 有可靠 PDF 文字坐标和本地几何分割证据的候选可以继续。
- 无法证明角色、款号、尺码或裁框的候选 fail-closed，记录“待人工确认”，不混入图包。

### 本地验证和裁图

模型只提供候选框，最终裁图由本地代码完成：

1. 校验归一化框范围、最小面积和宽高比。
2. 适量外扩，避免切掉吊牌边线、条码或洗唛文字。
3. 对裁图再次执行 OCR，核对当前款号和目标尺码。
4. 验证裁图不是空白、背面 Logo、严重截断或重复图。
5. 等比缩放并放到 800×800 白底画布，不拉伸。

吊牌写为 `yq1`，洗唛写为 `yq2`。多款色需要并存时沿用现有款色前缀命名能力；款色无关且内容相同的通用洗唛去重。

## 结果表和日志

每个被分析的标签候选至少记录：

- 原文件名和云盘路径。
- 目标角色。
- 是否命中现成 yq 短路。
- OCR/PDF 提取的款号、色号、尺码。
- 模型和置信度。
- 入选、剔除、跳过或失败原因。
- 最终裁图路径和输出文件名。

关键日志需要能区分：

- “现成 yq 已锁定，跳过对应 PDF”。
- “手写占位图已剔除”。
- “无吊牌/无水洗废图已剔除”。
- “选中 110”或具体的尺码回退原因。
- “模型不可用，可靠本地证据继续”与“证据不足 fail-closed”。

## 错误处理

- 单个 PDF 损坏、单页渲染失败或单个模型超时，不影响其他款号和普通商品图整理。
- 缺失角色没有可靠候选时，结果表明确记录缺失，不生成伪造 yq。
- 裁图后二次 OCR 与当前款号冲突时拒绝输出。
- 不因模型失败退回到“纯款号 PDF 默认洗唛”或固定框盲裁。
- 所有异常都保留行级原因，不能只写通用“处理失败”。

## 测试设计

### 单元测试

覆盖以下行为：

- `yq1/yq2` 变体识别及角色边界。
- `yq1` 只短路吊牌、`yq2` 只短路洗唛。
- 两者齐全时不提交任何 PDF/AI 标签任务。
- 不带款色前缀的 yq 建立款号级短路，带款色前缀的 yq 只短路对应款色。
- 手写覆盖、无吊牌、无水洗和错误款号拒绝。
- 110、最近的大于 110、最大的小尺码三层排序。
- 完整尺码表洗唛不被误拆。
- PDF 多页多单元裁框、背面 Logo 拒绝和重复图去重。
- 模型一致、模型分歧复核、模型不可用本地兜底和 fail-closed。
- 新处理器只从 `prepare_upload_package` 分支调用。

### 边界回归

必须证明以下任务未受影响：

- `batch_label_tile_download`

- 鞋品图包

### 真实样例

先运行 `201426105102`，通过后才运行 `202426107206`。

`201426105102` 验收：

- 现成 yq 按角色短路对应 PDF。
- 错误款号标签不得入包。
- 最终 `yq1/yq2` 内容角色与命名一致。
- 手写占位和“无吊牌/无水洗”素材不在结果目录。

`202426107206` 验收：

- 四页合格证 PDF 能识别两个色号及独立标签单元。
- 每个需要补吊牌的款色选择 110 尺码；不能选择 90，也不能裁出背面 Logo。
- 裁图完整、可读、800×800 白底且不拉伸。
- 洗唛已有有效 `yq2` 时不重复从 PDF 生成。

另外直接用用户提供的两张手写占位图片做识别冒烟测试，两张都必须被判为废图。
