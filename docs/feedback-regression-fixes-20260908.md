# 抓虾反馈与性能鲁棒性修复总结

2026-09-08。处理「抓虾反馈」群自 9 月 5 日 09:00 起的反馈，并完成性能、适配性与故障路径审查及修复。版本保持 2.5.3，本次交付为本地源码提交。

## 最终行为

| 范围 | 改动与效果 |
|---|---|
| 逛逛/搜推发布 | 提交一次后切换到轮询阶段，按任务 token、行号、入口隔离回执。避免 120 秒接口等待超过 60 秒阶段预算；回执丢失或超时进入结果待核实状态，不重发 POST。 |
| 通用脚本超时 | 默认不刷新、不重放超时阶段，提示先核实平台结果；仅显式声明只读/幂等的脚本允许一次超时重试。 |
| 停止与异常导出 | 共用短视频缓存恢复，合并并去重 partial_data，保留已完成行与内容 ID；等待发布回执时标为待核实。任务停止提示展示后端具体原因。 |
| 后端恢复 | 区分健康校验暂不可达和运行时不兼容。单次校验不可达进入 degraded，保持原端口；恢复后复用原进程。 |
| 工作区文件处理 | 扫描、哈希、删除及清单读写移到复用 Worker。按工作区文件快照维护哈希，只重算变化文件，移除旧版本与已删除文件的缓存。 |
| 工作区同步与清理 | 扫描只允许一个在途请求；清理期间暂停扫描，并使清理、切换目录、卸载前的旧扫描失效；每 25 张及结束时更新删除进度。 |
| 图片预览一致性 | 请求绑定身份和工作区。图片替换、工作区清空/切换/卸载后，旧请求不能写回缓存、错误状态或清除新请求的 loading 状态。 |
| 缩略图 | 使用既有 Python/Pillow 异步解码并缩放，限制并发 2，保留方向、宽高比及透明背景处理。损坏/截断图片明确失败，不把系统文件图标当作图片。 |
| PDF 预览 | 渲染、读图、编码整体搬到独立 Worker；每次生成独立输出目录；增加输入大小、页数、总像素边界，防止无界资源占用。 |

- 新增/扩展行为回归覆盖：发布仅提交一次、回执超时不重发、停止结果恢复、只读重试契约、健康校验波动、清理/切换竞态、2,001 张图片增量哈希、预览失效、解码失败释放并发槽及真实 PDF/图片处理。

完整测试在含既有本地改动的工作区运行；本提交仅纳入反馈及鲁棒性修复，不包含并行的 Manifest v2/SDK/产品文档改动。
